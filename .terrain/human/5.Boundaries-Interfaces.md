# System Boundary Interfaces

This document describes every way external actors interact with CLV3000 — command-line flags, configuration files, bundled directory layout, and environment variables. Understanding these boundaries is essential for deployment, scripting rescue workflows, and integrating CLV3000 into IT toolchains.

## Command-Line Interface

CLV3000 is primarily a GUI application, but its CLI flags enable automation, Explorer integration, and silent background operation. All parsing happens in `src/lifecycle.rs` and `src/main.rs`.

### Main Executable

**Binary**: `clv3000.exe` (Windows) / `clv3000` (macOS)

| Parameter | Required | Default | Meaning |
|-----------|----------|---------|---------|
| *(no flags)* | — | — | Launch with main window visible |
| `--tray-only` / `--tray` | no | false | Start silently in system tray without showing a window. On Windows, runs a Win32 message loop before eframe to avoid flash-window behavior (`src/main.rs:95-105`). |
| `--show` | no | false | Show the main window. If another instance is running, forwards a show request via IPC (`src/single_instance.rs:114`). |
| `--scan-path=<path>` | no | — | Scan a specific file or folder. Used by Explorer context menu (`src/lifecycle.rs:86`). Takes precedence over `--tray-only`. |
| `--scan-path <path>` | no | — | Alternative syntax accepting the path as the next argument (`src/lifecycle.rs:90-94`). |
| `--force-quarantine <orig> <dest>` | no | — | **Windows only.** Internal UAC elevation helper — not intended for direct user invocation (`src/main.rs:34-43`, `src/lifecycle.rs:102`). |

**Usage examples**:

```bash
# Normal launch
clv3000.exe

# Silent tray startup (autostart uses this)
clv3000.exe --tray-only

# Scan a specific path (Explorer context menu)
clv3000.exe --scan-path="C:\Users\test\Downloads\file.exe"

# Bring existing instance to foreground
clv3000.exe --show
```

### Environment Variables

| Variable | Meaning |
|----------|---------|
| `CLV3000_ALLOW_MULTIPLE_INSTANCES` | When set, bypasses the single-instance lock for development debugging (`src/single_instance.rs:58-60`). |

## Configuration File

User settings persist in a TOML file managed by `AppConfig` in `src/config.rs`.

**Location**:
- Windows: `%APPDATA%\CLV3000\config.toml`
- macOS: `~/Library/Application Support/CLV3000/config.toml`

| Field | Type | Default | Meaning |
|-------|------|---------|---------|
| `last_quick_scan` | object? | null | Timestamp, threat count, and scanned count from the most recent quick scan |
| `last_full_scan` | object? | null | Same structure for the most recent full scan |
| `ignored` | array | `[]` | Threats the user chose to ignore — same path + virus name won't alert again |
| `quarantined` | array | `[]` | Records of files moved to quarantine with original path and stored filename |
| `scan_removable_drives` | bool | `false` | When true, full scan includes USB/removable drives — can significantly extend scan time |

**Example configuration**:

```toml
scan_removable_drives = false

[[ignored]]
path = "C:\\temp\\old_threat.exe"
virus_name = "Eicar-Test-Signature"

[[quarantined]]
original_path = "C:\\Users\\test\\malware.exe"
virus_name = "Win.Test.EICAR"
quarantined_at = "2026-08-25T12:00:00"
stored_name = "a1b2c3d4e5f67890.quarantined"
```

## Bundled ClamAV Layout

For portable deployment, place ClamAV alongside the executable. Path resolution is handled by `src/paths.rs`.

```
<exe_directory>/
  clv3000.exe
  clamav/
    clamscan.exe
    freshclam.exe
    *.dll                    # libclamav and dependencies
    database/
      main.cvd               # Signature database files
      daily.cld
```

On macOS `.app` bundles, ClamAV may also reside at `Contents/Resources/clamav/` (`src/paths.rs:19-27`). If the engine is missing, the scan page displays "scan engine not found" rather than crashing (`src/scan/engine.rs:74-84`).

## System Integration Points

These are not CLI flags but OS-level registrations managed from the Settings page:

| Integration | Platform | Mechanism | Source |
|-------------|----------|-----------|--------|
| Autostart | Windows | `HKCU\...\Run` with `"<exe>" --tray-only` | `src/autostart.rs:35-36` |
| Autostart | macOS | `~/Library/LaunchAgents/*.plist` | `src/autostart.rs` |
| Context menu | Windows | `HKCU\Software\Classes\*\shell\CLV3000Scan` | `src/context_menu.rs:42-45` |
| Single-instance IPC | Windows | Named mutex + event objects + `scan_request.txt` | `src/single_instance.rs:48-54` |
| Single-instance IPC | macOS | Unix domain socket `clv3000.sock` | `src/single_instance.rs:6-8` |

## Integration Recommendations

**USB rescue kit**: Copy `clv3000.exe` + `clamav/` directory to a USB drive. Run `freshclam.exe --datadir=clamav\database` before first use, then launch scans via GUI or `--scan-path` for scripted batch operations in WinPE.

**Everyday protection**: Enable autostart in Settings so CLV3000 launches with `--tray-only` on boot. Enable Explorer context menu for one-click file scanning.

**Development preview**: Build on Linux to preview UI interactions. Real scanning requires Windows or macOS with ClamAV installed or bundled.
