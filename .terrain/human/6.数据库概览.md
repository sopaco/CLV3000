# 数据库概览

---

## 统计摘要

CLV3000 **没有使用任何数据库管理系统**。对仓库做全量扫描后，未发现 `.sql`/`.sqlproj` 文件、没有 `migrations/`/`sql/`/`db/`/`database/` 目录、没有任何 ORM 依赖（`Cargo.toml:6-17`），也没有数据库配置文件——因此本项目不存在数据库建模，本文档以"数据持久化说明"的形式呈现。

| 类型 | 数量 |
|------|------|
| 内部数据库表 | 0 |
| 视图 | 0 |
| 存储过程 | 0 |
| 外部病毒签名文件 | 由 freshclam 管理（`.cvd`/`.cld`，数量动态） |
| 程序自有持久化文件 | 1（config.toml） |

---

## 为什么不需要数据库

这个决定不是"没想到"，而是被产品定位逼出来的合理简化。CLV3000 是一个"扫完即走"的手动杀毒工具：它**不做实时防护**、**不做历史报表**、**不做多用户数据**，全部运行时状态（威胁列表、扫描进度、资源采样）都活在进程内存里、用 mpsc channel 跨线程传递，程序退出即消失——这正好符合"按需扫描、不留痕迹"的使用心智。一个为了记"上次扫描时间和忽略列表"而引入 MySQL/SQLite 的杀毒小工具，本身就是对"老机器优先"这个约束的背叛。

它真正需要记住的数据只有两类：用户偏好（忽略列表、可移动盘开关）和上次扫描摘要（`ScanRecord`）。这两类数据量加起来不到几十 KB，单文件 TOML 绰绰有余。CLV3000 的数据持久化需求由下面两套"文件级"方案解决：

1. **配置与状态**：`%APPDATA%\CLV3000\config.toml`（`src/paths.rs:43-45`、`src/config.rs:22-31`）。存放上次扫描摘要（`ScanRecord`）、忽略列表（`IgnoredEntry`）、可移动盘开关。用 serde + toml 序列化，加载失败回退默认值（`unwrap_or_default`）。这是唯一由程序**自己读写**的持久化数据。

2. **ClamAV 病毒库**：`<exe>\clamav\database\` 下的 `*.cvd / *.cld` 文件（`src/paths.rs:28-30`）。这是"数据库"这个词在程序里唯一出现的地方，但它**不属于本程序管理**——它由外部 `freshclam.exe` 下载/维护，`clamscan.exe` 读取用于签名比对，CLV3000 只负责定位目录路径。

3. **内存态**：所有运行时状态（威胁列表、扫描进度、资源采样）都保存在进程内存中，用 mpsc channel 跨线程传递，程序退出即消失——与"手动扫描、扫完即走"的产品定位一致。

## 实体关系图

由于本项目不涉及数据库建模，不存在实体关系图。若未来需要引入结构化数据（例如：扫描历史趋势、多台机器管理），单文件 TOML 会最先成为瓶颈，届时最自然的方向是引入 SQLite（嵌入式、零服务、单文件，依旧符合"绿色分发"的约束）。
